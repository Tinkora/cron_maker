# 产品范围

[English](./PRODUCT_SCOPE.md)

## 产品说明

cron_maker 是一个专注的浏览器工具，用于创建、检查、解释和预览 Unix/Vixie 五字段 cron 调度。它帮助开发者和运维人员确认表达式及其时区行为，同时无需将调度数据发送到应用服务。

## 用户与任务

| 用户 | 需要完成的任务 |
| --- | --- |
| 开发者 | 无需记忆每个字段即可构建或验证五字段 cron 表达式 |
| 运维人员 | 安装调度前确认后续执行时间 |
| 评审者 | 将表达式与英文和简体中文描述对照检查 |
| 分布式团队 | 跨夏令时变化按命名的 IANA 时区计算本地时间执行点 |

## 0.1 版本范围

### 浏览器应用

- 静态应用，不包含应用后端、账号、分析或调度存储
- 默认英文，并提供完整简体中文切换
- 可视化五字段控件和原始表达式编辑器
- 内置常见预设和一键复制表达式
- 后续执行表展示由内置 tzdb 生成的所选时区时间、UTC 和相对时间
- 可选择 5、10、20 或 50 次执行

### Cron 处理

- 严格使用五个 Unix/Vixie 字段：分钟、小时、日期、月份和星期
- 支持通配符、单值、逗号分隔列表、闭区间、步进和范围步进
- 在适用字段支持数值及标准 `JAN` 至 `DEC`、`SUN` 至 `SAT` 名称
- 星期日可使用 0 或 7
- 日期和星期同时受限时采用 Vixie OR 匹配
- 支持产品契约中列出的七个 `@` 别名
- 表达式规范化、验证、英文描述和简体中文描述
- 原始表达式输入在 trim 前最多 256 UTF-8 bytes

### 调度预览

- 计算严格晚于所提供 Unix timestamp 的执行点
- 支持 UTC 便捷计算和调用方选择的 IANA 时区计算
- 通过内置时区数据库执行感知 DST 的本地时间调度和所选时区格式化
- DST 跳变中跳过不存在的固定本地时间，DST 回拨中返回重复本地时间的两个实例
- 每次 core 调用返回 0 至 50 个执行点
- WASM 边界返回 UTC Unix seconds 和 ISO 8601 文本

### 开发者接口

- 用于解析、描述和调度的 Rust core crate
- 浏览器应用使用的 `wasm-bindgen` functions
- 与 JavaScript 兼容的数据对象和机器可读错误码

精确的输入和输出行为以[产品契约](./CONTRACT.zh-CN.md)为准。

## 明确的非目标

0.1 版本不提供：

- 六字段或七字段 cron 表达式、秒字段或年份字段
- `L`、`W`、`#`、`+` 或 `?` 等非 Vixie 修饰符
- Quartz 或 AWS 调度方言
- 调度守护进程、作业执行、进程管理、监控、告警或 crontab 安装
- 从自然语言生成 cron 表达式
- 账号、已保存调度、同步、协作或历史记录
- 托管 API、服务器端计算、CLI、MCP 集成或 Agent Skill
- npm package、crates.io release 或稳定 1.0 API
- 原生移动或桌面应用

这些排除项使产品契约与已经实现并测试的行为保持一致。

## 隐私边界

应用不会主动传输输入的表达式或计算得到的调度数据。解析、描述和调度均在浏览器加载的 WASM 中进行。静态托管仍会向托管方暴露普通资源请求元数据，浏览器扩展、被攻破的浏览器或被修改的部署也可能观察页面内容。复制表达式会将其写入系统剪贴板。

## 范围变更门禁

拟议能力只有满足以下条件才能进入产品：

1. 当前五字段工作流无法充分解决的真实用户问题
2. 边界清晰的实现方案和维护负责人
3. 隐私、安全、兼容性与资源限制分析
4. 面向结果的 Rust 测试及切实可行的浏览器验证计划
5. 含义对等的英文和简体中文文档更新
6. 是否变更公开契约的明确决定

在实现和验证完成前，提案必须始终明确标为拟议内容。
