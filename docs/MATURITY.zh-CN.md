## 当前状态

cron_maker 是 1.0 之前的代码库。核心五字段路径已经实现，并有 Rust 和浏览器测试覆盖，但此状态不表示远端仓库、托管部署、tag、package 或 GitHub Release 当前已经可用。

| 范围 | 状态 | 证据与限制 |
| --- | --- | --- |
| 五字段解析 | 在契约范围内可用 | Rust 测试覆盖单值、名称、列表、范围、步进、别名、无效范围、字段数量、拒绝的修饰符和 byte 限制 |
| 英文和中文描述 | 在契约范围内可用 | Rust 测试覆盖常见步进、时间、星期和月/日场景；描述措辞并不是对每个表达式的形式化语义证明 |
| IANA 时区调度 | 在契约范围内可用 | Rust 测试覆盖 UTC progression、无效时区、次数限制、调度范围、DST 跳变和回拨，以及 IANA 2026c 的 Morocco 调度与本地 offset 变更 |
| 浏览器应用 | Beta | Playwright 覆盖真实 WASM、语言切换、表达式构建、时区选择、自动预览刷新、键盘 tab、请求隐私、console 状态和 overflow |
| Rust API | 1.0 之前 | 公开且经过测试，但 type 和 signature 在 1.0 前可能变化 |

| 无障碍 | Beta | 已测试语义化控件、无障碍 label、实时状态、键盘 tab 和四个 viewport；没有第三方审计 |
| 安全 | 尽力维护 | 浏览器本地架构和有界输入降低了暴露面；没有外部审计或服务级响应承诺 |

## 已验证的不变量

仓库包含用于证明以下行为的测试：

- 只接受 Unix/Vixie 五字段方言。
- 六字段和七字段表达式会被拒绝。
- 在公开契约覆盖的位置会拒绝 `L`、`W`、`#`、`+` 和 `?` 扩展。
- 可以解析标准月份和星期名称、列表、范围与步进。
- 支持的别名保留规范化小写别名，并展开为五个字段。
- 超过 256 UTF-8 bytes 的原始表达式输入会在 trim 前被拒绝。
- 受限的日期和星期字段采用经过测试的 Vixie OR 规则。
- 请求超过 50 次执行会被拒绝；请求 0 次会返回空列表。
- IANA 时区调度会跳过已测试的 DST 跳变，并在已测试的回拨中返回两个 timestamp 实例。
- 内置 IANA 版本公开且固定为 `2026c`，并在调度与所选时区 `local_iso` 格式化中覆盖 Morocco 永久改用 UTC 的变更。
- 超出已记录前推格里高利历调度范围的起始 timestamp 会被拒绝，而不会产生误导性空结果。
- WASM 结构化结果是与 JSON 兼容的 JavaScript object。
- 浏览器默认使用英文，并提供完整简体中文路径。
- 长时间打开的浏览器会在分钟边界以及恢复可见或焦点后刷新执行时间。
- 浏览器测试在配置的运行中没有观察到意外外部请求、失败 response、console warning 或 error、水平 overflow。

这些测试通过不代表项目已经认证所有 cron 实现、IANA 数据库版本、浏览器、locale、辅助技术或运行环境。

## 兼容性基线

- 最低支持 Rust 版本：1.85
- Rust edition：2024
- Web build target：`wasm32-unknown-unknown`
- 内置 IANA 时区数据库：`2026c`
- 浏览器测试 runtime：Node.js 24 或更高版本
- 已测试浏览器引擎：Playwright 中的 Chromium
- 自动化 viewport 宽度：375、768、1024 和 1440 像素
- 应用和一等文档语言：英文与简体中文

仓库必须持续使用 Rust 1.85 编译。只在更新的 stable compiler 上运行 CI 不能替代 MSRV 检查。

## 已知限制

- 只支持 Unix/Vixie 五字段 cron；没有秒字段或年份字段。
- `L`、`W`、`#`、`+` 和 `?` 被有意设为不支持。
- 不支持 Quartz 和 AWS 方言。
- 产品只预览时间，不安装、执行、监控调度作业，也不提供告警。
- 描述文本来自已验证语法，但不能替代对关键调度的人工评审。
- DST 行为取决于内置 IANA 时区数据库以及 scheduler 已记录的跳变和回拨行为。
- 内置数据库属于发布 dependency；IANA 发布新版本后必须显式更新 dependency，并增加受影响时区的回归测试。
- 调度搜索受已记录的前推格里高利历范围限制，上限为 5000 年起点。
- 应用没有账号、已保存调度、同步、历史记录或协作。
- 没有 CLI、MCP 集成、Agent Skill、托管 API、npm release、crates.io release 或稳定 1.0 API。
- Chromium 在四种宽度下的自动化不等同于多浏览器兼容保证。
- 本文档不假设任何公开 Release 当前可用。

## 版本策略

项目计划为未来发布遵循 Semantic Versioning，但 1.0 之前的版本可能在 minor release 中修改公开契约。每个用户可见或 API 可见变更都必须记录在 changelog。Patch release 应在所属 minor line 内保持向后兼容，除非继续保留错误或不安全行为并不合理。

达到 1.0 的条件包括：

1. 至少完成一个公开发布周期并记录升级经验
2. 有意识地评审 Rust 和 WASM API
3. 五字段语义和错误码策略稳定
4. 发布产物可复现，并强制执行供应链检查
5. 有持续维护的多浏览器和无障碍验证矩阵
6. 有持续使用证据和足够的维护者连续性
